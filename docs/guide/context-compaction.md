# 上下文压缩用哪个模型

压缩总用会话当前的模型写摘要，主会话、子智能体、侧聊和手动 `/compact`（或 `@compact`）都一样，
设置里没有单独的压缩模型可选。

原因是缓存：摘要请求从上一次主请求原样分叉，前缀照常命中缓存，基本只付摘要输出的钱。缓存按模型
分，换一个模型写摘要，整段历史就要按原价重读一遍——压缩时上下文已经快满，这往往是整段对话里最
贵的一次请求。

旧版本在「设置 › 智能体 › 会话」里选过的 `compact` 模型留在配置文件里，不再被读取，也不影响别的
设置。是否触发压缩、保留多少近期消息，由会话模型的上下文窗口决定，见
[../architecture/context-assembly.md](../architecture/context-assembly.md)。
