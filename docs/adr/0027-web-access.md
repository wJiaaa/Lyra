# ADR-0027：Web 访问——桌面端把自己的界面发给浏览器

- 状态：已采纳
- 日期：2026-09-27
- 相关：部分恢复 [ADR-0001](0001-mobile-hosts-the-desktop-renderer.md) 的「一份界面、两个宿主」；
  修订 [ADR-0026](0026-remove-mobile-and-relay.md)、[ADR-0012](0012-one-contract-not-three.md)

## 背景

ADR-0026 删掉了移动端，也就失去了「在电脑之外看进行中的回合、批准操作、继续追问」。想要的是
像 ZCode 那样在浏览器里看，但调研 ZCode 后发现它的 `zcode --web` 是一个独立的服务进程：与桌面端
共用存储，却各跑各的 agent，彼此没有实时推送——只看得到对方写进库里的历史。

## 决定

桌面端托管，实时同步。设置里打开后，主进程在局域网上起一个 HTTP + WebSocket 服务：发送渲染进程的
构建产物，按白名单转发 `window.lyra` 调用，并把窗口收到的会话事件同样推给浏览器。浏览器里由
`services/web-bridge.ts` 按契约方法表搭出网络版 `window.lyra`，界面代码不分宿主。

- 能力：对话可操作（看、发、停、审批），不能改设置、不能碰终端与文件写入。白名单写在契约的
  `WEB_METHODS` 里，主进程拒绝名单外的调用，渲染进程用 `available()` 不画名单外的控件。
- 访问：监听所有网卡，令牌链接换 HttpOnly Cookie；不做公网中转，不做配对 App。

复用了 ADR-0026 删掉的同步服务里经过事故检验的部分：白名单与参数校验（`web-rpc.ts`、
`@lyra/contract/args`）、新建会话限定在已打开的项目、远端附件路径不作数、局域网地址排序。
没有恢复的：手机外壳、中转、配对码、手机可写设置、每个方法上的 `remote` 声明（换成一份 48 项的名单）。

## 后果

**得到的**：手机、平板、另一台电脑的浏览器都能跟进同一个回合，界面与桌面端同版本，不经过应用商店。

**接受的代价**：

- 桌面端必须开着，且在同一网络里。跨公网要自己加反向代理或 VPN。
- 服务是明文 HTTP。局域网里的旁路者能看到流量与 Cookie——只在可信网络里打开。
- 加 IPC 时又要回答一次「浏览器能不能调」：默认不能，要加就改 `WEB_METHODS` 并写明理由。
- 浏览器里按宿主降级的分支回到了渲染进程（`onWeb()` / `available()`）。

## 什么时候该重新考虑

需要跨公网访问时：优先让用户自己的反向代理 / Tailscale 解决，其次才考虑 ADR-0002 那种不知道
令牌的中转。需要离线查看时：缓存这一份界面，仍然不画第二套。
