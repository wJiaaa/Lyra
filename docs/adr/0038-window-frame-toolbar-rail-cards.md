# ADR-0038：工作区窗口走一套外框——顶栏、毛玻璃上的侧栏、一张张卡片

- 状态：已采纳；第 1、2 条（顶栏）2026-10-09 撤回，见各条
- 日期：2026-10-05（上游 kittors/Lyra 的 ADR-0031，2026-10-06 合入本 fork 时改号）；2026-10-09 修订第 1–4、7 条
- 相关：`app/window/WindowToolbar.tsx`（`DragBand`、`WindowButtons`、`WindowHeader`）、
  `app/window/WindowControls.tsx`（`NavButtons`）、`app/nav-history.ts`（`useNavShortcuts`）与 `lib/nav-history.ts`、
  `shared/window-chrome.ts`（`MAIN_WINDOW_ROW_OFFSET`）、`features/dock/DockView.tsx`（`startInset`）、
  `features/sidebar/NotificationsMenu.tsx`；ADR-0023

## 背景

用户给了一张参考截图：窗口顶上横贯一条工具栏（红绿灯、后退、前进、侧栏开关，单个会话时它的标题），左边一列图标，
侧栏和内容合在工具栏下面的一块面板里，中间一条细线。

我们原来的做法是把窗口顶行「分给」各块：红绿灯画在侧栏左上角，侧栏开关浮在角上，会话的标题栏就是它那张卡片的
第一行，整排往下挪 5px 去和卡片对齐（`MAIN_WINDOW_ROW_OFFSET`）。于是每张碰到窗口角的卡片都要给红绿灯或
Windows 的系统按钮让位（`startInset`、`cornerReserved`、拉取请求页的 `prInsets`），而且这套让位规则在 macOS 和
Windows/Linux 上是两条路径。

## 决定

1. **（2026-10-09 撤回）顶栏属于窗口。** 主窗口在所有桌面平台上都画一条顶栏：macOS 40px（红绿灯居中，y=13），Windows/Linux 沿用
   原生 header 的 32px。顶栏下面的东西一律不再为窗口的角让位——`layout.tsx` 的 `framed` 和 `headerBar` 一样被
   当作「上面有一条带子」读。会话窗口、面板窗口不变，仍是自己的 44px 标题栏。
   撤回：顶栏一直是一整行空白，标题、标签条、收起按钮陆续搬进卡片之后它只剩红绿灯和三颗按钮，用户要回到原来
   的顶行。现在和外框之前一样：红绿灯在侧栏左上角，后退、前进、侧栏开关浮在它旁边（`WindowButtons`），每张
   卡片的标题栏就是窗口的顶行，整排低 `MAIN_WINDOW_ROW_OFFSET`（5px）和卡片对齐；侧栏收起时碰到左上角的卡片
   给这几颗按钮让位（`startInset`）。Windows/Linux 仍是那条 32px 的原生 header（`WindowHeader`）。
2. **（2026-10-09 撤回，随第 1 条）单屏时标题进顶栏，多屏时各屏自留。** 只有一屏时，它的标题和「…」画在顶栏里、对齐内容区的左缘，面板按钮
   在顶栏右端，对话里不再留 44px 标题栏（`DockPane` 的 `reserveHeader`）。两屏以上每一屏仍有自己的标题栏——
   顶栏只有一条，说不清是哪一屏的。面板始终在顶栏下面，所以「标题栏不盖面板」那条规矩照旧成立。
   单屏的标签页排法下，右栏的标签条连同它的刷新、弹出、全屏也画进顶栏（2026-10-07），左缘对着右栏的分隔线、
   跟着它走，右栏里不再另占一行（`features/dock/ToolbarPanelBar.tsx`，经 `app/window/toolbar-slot.ts` 的
   portal）。开面板的按钮属于会话，跟着会话一侧停在右栏分隔线左边，右栏开着时窗口角上只剩右栏自己的
   刷新、弹出、全屏——七颗挤在一处分不清哪颗管什么。没开右栏时它们照旧在顶栏右端。多屏时仍是每格自己的标题栏。
   撤回后每一屏都有自己的标题栏，右栏的标签条和按钮回到右栏卡片的第一行；按钮用 28px、图标 13px，和会话
   标题栏那一排一样大（`tabs.css` 末尾）。收起右栏的按钮在右栏标题栏最右，收起后展开按钮在会话标题栏最右；
   只有单屏能收——收没收是整扇窗口一个开关。
3. **去处和会话都在侧栏里。** 侧栏从上到下是新对话、拉取请求、已安排、插件，接着是会话列表，设置在侧栏底部
   （本 fork 没有应用内更新，所以没有更新提示）。拉取请求、已安排、插件三页各自把列表画在自己页面里。
   第一版把这些去处放进窗口左边一列图标栏，侧栏跟着它换成那一页自己的东西（经 `app/nav-slot.tsx` 的 portal）；
   2026-10-09 撤掉了：多一列图标、侧栏内容随页面变，用户要的是原来那一栏，两样连同 portal 一起删掉。
4. **后退和前进是真的。** 历史记录观察 store 里的「视图 + 当前会话」，而不是让每个打开会话的地方自己报告；
   规则（同一处只记一次、往回走之后新去一处会截掉前面的、删掉的会话和已经不在的空白对话跳过）在
   `lib/nav-history.ts`，有单测。⌘[ ⌘]（Windows/Linux 上 Alt+←/→）和鼠标侧键也走它；在输入框里不触发。
   顶栏撤掉后两颗按钮在红绿灯旁边、侧栏开关之前（`NavButtons`），设置页也一样；macOS 上第一颗离窗口左边
   86px，图标和绿灯之间约 16pt——78px 时三颗按钮读起来像第四、五、六颗灯。
5. **面板只有标签页一种排法。** 起初默认分栏、标签页留在外观里可选，理由是分栏能把面板拖到对话的另一侧。
   2026-10-07 起分栏排法连同拖动把手、落点预览和键盘挪格一起删掉了，外观里不再有「面板」这一项：所有面板
   收在对话右侧一栏，每个一个标签。
6. **铃铛有用了。** 它从 09-07 起就是一颗没有任何处理的按钮；现在列出等你批准、出错、已完成的会话（当前这一屏
   除外）和没看过的定时任务失败，点一行去那里。
7. **侧栏铺在窗口材质上，每块内容一张卡片，彼此隔 4px。** macOS 上侧栏不刷底，透出窗口的毛玻璃；会话、右栏、
   分屏和拉取请求等页面各是一张圆角卡片（`DockPane` 的 `ly-dock-card`、`.ly-card-page`），卡片之间、卡片和
   侧栏及窗口边缘之间都露 4px 窗口色（`.ly-frames` 的 2px 加卡片的 2px 外边距），窗口顶上也是 4px。
   缝上不画线：悬停时出现一截 3×30 的把手，跟着指针沿缝走，拖动时变成强调色。
   第一版（10-05）是「一块面板，里面没有卡片」：侧栏和内容在同一圈圆角里，中间一条 1px 线，侧栏是实色。
   2026-10-09 改回卡片：侧栏没有毛玻璃、面板之间没有缝，用户看了说不是原来的样子。钉住的项目名底下没法再垫
   实色，Chromium 在侧栏滚动容器里的 `backdrop-filter` 也模糊不了什么，所以改成让滑进标题底下的会话行自己
   淡掉（`tabs.css` 的 `ly-under-head`）。

## 后果

- 顶栏撤掉后，窗口角的让位又回到各处：macOS 上碰到左上角的卡片让红绿灯和三颗按钮（`startInset`、
  `cornerReserved`、拉取请求页的 `prInsets`），Windows/Linux 上一切在 header 下面，不让位。
- 有毛玻璃时侧栏透明；没有时（非 macOS、外观设置里关了「窗口毛玻璃」、或系统关掉了透明度）侧栏和钉住的项目名都是 `--color-sidebar` 实色。
  内容卡片比原先的面板往里缩 4px，`hold-column-width.ts` 量会话栏宽度时要减掉卡片那一圈，否则开合侧栏时
  正文宽度在第一帧之后还会跳 5–6px。
- 设置页走同一套排布（红绿灯那一行、毛玻璃侧栏、一张卡片），从对话切到设置时动的只有内容。

## 什么时候该重新考虑

- 如果要再加回一条顶栏：先回答它上面放什么。这一次标题、标签条、收起按钮都搬进卡片之后，它只剩一行空白。
- 如果标签页排法要成为默认：先让标签能拖出来、能拖到另一侧，再换默认。
