# ADR-0046：`edit` 改回按原文替换，去掉行号补丁

日期：2026-10-12

状态：已采纳

## 背景

`edit` 原先首选行号补丁：`read` 在文件头给一个四位 tag，编辑时引用 tag，写
`REPLACE 7-9` / `INSERT AFTER 40` / `DELETE 3-3`，只给替换行。`old_string`/`new_string` 留着，但标成
「Legacy」。选它的依据是一次自测：在本仓库源码上 270 次真实调用，gemini-2.5-flash-lite 首次成功率
78% → 96%，输出 token 少一半；更要紧的是字符串替换有 10 次「锚点落在一个看着合理的地方、工具报成功」，
行号补丁的失败全是能读懂、能重试的拒绝。

这套设计后来又长出了不少配套：tag 冲突、改完后旧 tag 换算到新行号（最多 8 个版本）、「内容看过」和
「在这个 tag 下这个行号显示过」两层已读记录、unified diff 写法的守卫（`-旧行` 被当成正文写进文件）。

## 为什么改

**最小的改动成了最贵的改动。** 行号补丁的单位是行。换一个词，要把整行原样重打一遍；一段一行的
文本（LaTeX、Markdown 段落、压成一行的 JSON）一行上千字。Terminal-Bench 2.1 的 overfull-hbox 要在
`input.tex` 里换几个同义词，最长一行 1375 字。deepseek-flash 下，Plume 8 次全部先写了一个脚本去
批量套改动，而不是直接改文件（原因不只这一个，提示词也有份，见 `prompt/system.ts` 的注释）；有一次思考里明确担心：REPLACE 要整行重打，抄错一个字符就会被静默写进
文件。同一个模型在 opencode 里用 `oldString`/`newString`，一次发出 7 处改词，改一处编一次。

重打整行还把原来要防的那种失败换了个地方出现：整行重打时抄错一个字，那个错字会被当成改动写进去，
工具照样报成功。

**别家都按原文替换。** pi（`edits[].oldText/newText`，要求 oldText 越小越好）、maka、ZCode、
opencode、Claude Code 都是；Codex 的 apply_patch 靠上下文定位，也不靠行号。maka 的评测在同一个
harness 里换过三种编辑工具（str_replace_editor、apply_patch、fs），86 道题上测不出差别——编辑格式本身
不是完成率的主要变量，犯不上为它让最常见的小改动变贵。

**那次自测为什么不再起决定作用：** 它量的是单次编辑的首次成功率，模型是 gemini flash-lite，素材是
本仓库的源码（行短、结构规整）。它没有量到「换一个词要重打一千字」这种形状，也没有量任务能不能做完。

## 决定

- `edit` 只有一种写法：`old_string`、`new_string`、`replace_all`。`old_string` 必须唯一（重叠
  命中也算歧义），空串直接指向 `write`。描述里要求「`old_string` 尽量小、够唯一就行，长行上也一样」。
- 原文里找不到时，照 ZCode 依次试七种近似读法（`tools/edit-match.ts`）：弯引号当直引号、去掉抄进来的
  `12→` 行号前缀、反转义、`\uXXXX`、每行去首尾空白、忽略缩进、首尾两行对上且中间相似度 ≥ 0.8。第一种
  找到东西的读法说了算：只有一种文本就替换，几种不同的文本就拒绝。`replace_all` 不用后三种。
  `new_string` 按找到的样子写回：反转义、去行号前缀、原文是弯引号就换成弯引号。
- 去掉 tag：`read` 的文件头只剩 `[路径]`，`write`/`edit` 的结果里不再给 tag；`hunk.ts` 整个删掉。
- 原来保证安全的几条照留：文件必须先读过、读完之后没被别人改过。「改过」同 ZCode，看修改时间（取整到
  毫秒、只认更晚）和大小，不再比对内容哈希。
  改完回显改动处上下各一行，省掉一次重读。
- 不记哪几行显示过，同 ZCode：只看最近一次读是不是「没要求窗口却被截短了」——大纲视图、按行数或字数
  截断的整篇读。是的话 `edit`/`write` 一律拒绝，要它按 `offset`/`limit` 再读一次。最初的版本按行记
  「看过的地方」，跨行的 `old_string` 只查了第一行，漏掉的正是它要防的情况；补成逐行检查也只是在
  「匹配」之上再加一道——模型能写出那几行，说明它已经知道那里写的是什么。
- 几处改动在同一条回复里发几次 `edit`，不做一次多处的数组形式：顺序执行已经保证后一次看到前一次的
  结果，没有证据表明数组形式值得多一套参数。

## 代价

- 多处改动从一次调用变成同一条回复里的几次调用，结果条数变多。
- 失去了「行号对不上就拒绝」这层校验；由「匹配 + 唯一 + 读过且没被截短」代替。原来量到的「锚点落在
  看着合理的地方」那 10 次，前提是锚点不唯一或者没读过——这两种现在都会被拒。
- 读一个窗口就能改窗口外的文字。大纲视图之后哪一行都不能直接改，要先按窗口读一次，比按行记的时候
  多一次往返（那时声明行能直接改，折叠体的拒绝里会附上原文）。
- 近似读法会改到模型没逐字写对的文字：首尾锚定那一种，中间几行可以差两成。靠的是改完回显「现在是
  什么样」，模型从回显里能看出改到了哪里。
- 同样大小、同一毫秒内的改写看不出来；只碰了修改时间、内容没变也会要求重读。
- 弱模型上首次成功率可能回落。要量，用 `pnpm bench` 在同一套题上和改动前对照，不要再靠单次编辑的
  成功率下结论。
