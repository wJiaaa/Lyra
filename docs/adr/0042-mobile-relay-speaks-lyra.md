# ADR-0042：手机经中转连接，沿用 Lyra 中转协议

日期：2026-10-08

状态：已采纳；取代 ADR-0041 中「不提供中转」的部分，其余不变。

## 背景

ADR-0041 只支持直连、VPN 或 HTTPS 反向代理。实际用的时候手机多半在移动网络、电脑在家里路由器后面，两边谁也连不进谁，手机端等于不能用。上游 Lyra 已经有一个中转服务（ADR-0002，`packages/relay/server.mjs`），而且已经部署在用户自己的服务器上。

## 决定

Plume 不自带中转服务，两端直接说 Lyra 中转的协议，已部署的 Lyra 中转原样可用：

- 两端都往外连中转根地址，发 `{type:"hello", room, role}`；中转回 `waiting` / `ready` / `peer-left` / `error`，配上之后原样转发帧。
- 房间号是 `SHA-256("plume-relay\0" + 令牌)`，桌面和手机共用 `client-runtime/src/relay.ts` 里同一份纯 JS 实现（手机端 Hermes 没有可靠的 `crypto.subtle`）。
- 桌面 hello 不带 `assetKey`：Plume 手机是原生界面，不需要 Lyra 的网页资源通道，中转也就不会发 `asset_request`。
- 配上之后，电脑仍然要求手机出示令牌，和直连同一段代码（`MobileServer.open`）。只知道房间号的人进得了房间，过不了这一关。
- 配对码多一种形式：`plume://pair?relay=wss://…&token=…`。一个码只带一条路，手机不在几条路之间切换。
- 中转地址存在 `mobile-access.json` 的 `relay` 字段，桌面「设置 → 手机连接」里填。

## 取舍

- **没有端到端加密。** TLS 只保护手机到中转、中转到电脑这两段。中转能看到全部会话内容，以及认证那一帧里的令牌。用户明确决定先不做：中转部署在自己的服务器上。换成第三方或公共中转之前，必须先改成挑战应答（令牌不出两端）或端到端加密。
- **经中转同一时间只连一部手机。** Lyra 的房间只有两个位置，第三个连接会被拒绝而不是顶替（防令牌泄露后被人挤掉）。手机换网络后，旧连接要等中转判死（约一分钟）才能重连；期间手机端按 `role-full` 退避重试，不报错。
- 手机离开时中转只发 `peer-left`、连接不断，桌面在同一条连接上接下一部手机，所以会话状态挂在「一段配对」上，而不是挂在 socket 上。

## 影响

直连和中转共用同一套认证、限流和接口白名单，手机可调用的接口没有因为中转而变多。中转协议的兼容性由 `packages/desktop/test/mobile-relay.test.ts` 守着；那里的中转是照 Lyra 行为写的替身，升级 Lyra 中转后要拿真实的 `server.mjs` 再连一遍。
