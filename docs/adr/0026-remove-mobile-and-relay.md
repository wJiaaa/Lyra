# ADR-0026：移除移动端与中转服务

- 状态：已采纳；「在电脑之外操作 agent」由 [ADR-0027](0027-web-access.md) 以浏览器的形式补回
- 日期：2026-09-26
- 相关：取代 [ADR-0001](0001-mobile-hosts-the-desktop-renderer.md)、[ADR-0002](0002-relay-knows-nothing.md)；修订 [ADR-0012](0012-one-contract-not-three.md)

## 背景

移动端是一个 Expo 外壳：配对、扫码，然后在 WebView 里加载桌面端的界面。为了让它能用，仓库里
长出了一整套只为手机存在的东西：

- `packages/mobile`（Expo / React Native 应用）与 `packages/relay`（公网中转服务）
- 主进程的同步服务：HTTP + WebSocket RPC、配对令牌、局域网地址枚举、中转连接、手机可写设置的白名单
- 契约里每个方法的 `remote` 声明，以及渲染进程里按宿主降级的 `onPhone()` / `available()` 分支
- 发版流水线里的 Android / iOS 两个 runner、签名密钥、构建号、`expo prebuild`

这些东西的维护成本一直在付：每加一个 IPC 都要判断手机能不能调；每个界面改动都要想手机上怎么降级；
每次发版多两个 runner，其中 Android 那个决定了发版要等多久。

## 决定

移动端整体移除，产品只保留桌面端。连同只为它存在的部分一起删：`packages/mobile`、`packages/relay`、
主进程的同步服务与设置页的「移动端同步」、契约的 `remote` 字段、渲染进程的手机适配、CI 与发版里的
移动端构建。

`packages/core` 仍然保持平台无关——那条边界的理由（运行时不该认识某一个前端）不依赖移动端存在。
契约仍然是一处，只是消费者从三个变成两个：主进程按它注册，preload 按它生成。

## 后果

**得到的**：少两个包、一个网络服务、一条对外暴露的攻击面（配对令牌就是一台机器的操作权限）。
加 IPC 不再需要做「手机能不能调」的安全判断；界面不再有两个宿主；发版少两个 runner 和一把签名钥匙。

**失去的**：不能在手机上看进行中的回合、批准操作、继续追问。

**旧数据**：`~/.plume/settings.json` 里已有的 `sync` 段落不再被读取，留在文件里无害；配对令牌
随同步服务一起失效，不再授予任何能力。

## 什么时候该重新考虑

如果又需要在电脑之外的设备上操作 agent。那时先回头读 ADR-0001、ADR-0002 与这条的 git 历史：
「一份界面、两个宿主」和「中转不知道令牌」这两个决定本身仍然成立，删掉的是实现，不是理由。
