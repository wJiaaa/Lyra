# ADR-0053：项目按 id 认，会话记下自己的项目，先有项目再有文件夹

- 状态：已采纳
- 日期：2026-10-17
- 相关：core `config/project-roots.ts`、`config/project-folders.ts`、`session/types.ts`（`SessionMeta.project`）、
  `session/store.ts`（`create`、`move`）、`trajectory/fork.ts`、`config/settings.ts`（`ScheduledTask.project`）；
  desktop `src/lib/project-identity.ts`、`src/lib/sidebar-grouping.ts`、`src/store/workspace-slice.ts`、
  `src/store/project-folders.ts`、`src/features/settings/ProjectScope.tsx`、`electron/session-hub.ts`、
  `electron/peer-reach.ts`、`electron/scheduler.ts`；部分取代 ADR-0048 第二条

## 背景

用户报了三件事：

1. 文件夹 A 已经在项目 A 里，再新建项目 B、选同一个 A，项目 B 不出现。
2. 项目不该和文件夹绑在一起：应该是「这个项目里有这个文件夹」，而不是「有这个文件夹，所以才有这个项目」。
3. 项目默认用文件夹名命名，结果不能重名。

查下来是同一个根：**项目的身份就是它的主文件夹。**

- `ProjectEntry.id` 等于主文件夹路径。`createProject` 先按主文件夹找已有条目，找到就**覆盖**——用 A 建 B，是把
  项目 A 改名成 B、文件夹也换掉，A 没了。编辑、移除、归档、排序、侧栏分组全按 `path` 查，两个主文件夹相同的项目
  在哪儿都叠成一个。
- 会话不记自己属于哪个项目，只能拿 `cwd` 反推。`SessionMeta.projectId` 是 `cwd` 的哈希，`projectName` 是创建时的
  文件夹名，会话行、命令面板、通知上显示的都是它——改过名的项目、两个都叫 `app` 的项目，在这些地方分不出来。
- `openWorkspace` 打开任何文件夹都登记成项目；侧栏遇到不属于任何项目的会话，照它的 `cwd` 现造一个「项目」分组。
  「项目」成了「去过的文件夹」的别名。
- 之前的 `claimedFolders`（附加文件夹是别的项目的主文件夹时不吞它的会话）只是在其中一种情况下打补丁。

## 决定

1. **项目有自己的 id。** 新建一律 `crypto.randomUUID()`，不查也不覆盖已有条目；同一个文件夹可以在好几个项目里，
   做主文件夹或附加文件夹都行。名字只是名字，可以重名。编辑、移除、归档、排序、折叠、菜单、侧栏分组、
   `sessionOrder` 的 key 全部按 id。旧条目的 id 仍是路径，照样唯一、照样稳定，不迁移。
2. **重名时用路径区分。** 列表和菜单里在名字后面淡色带上父目录末尾那几级，刚好能分开为止（`pathHints`）：
   `~/work/a/app` 和 `~/work/b/app` 显示 `a` / `b`。整条路径试过：两行都是 `~/work/…`，正好截在分叉处。
3. **会话记下自己的项目：`SessionMeta.project`，存 `ProjectEntry.id`。** 不复用 `projectId`——那是文件夹的哈希，
   会话日志和项目记忆按它存放。在项目里新建、侧边聊天（跟父会话）、分叉、手机端新建、定时任务
   （`ScheduledTask.project`，建任务时取当前项目，`getOrCreateSession` 写进 meta）都写入它；`move` 记录带着它，
   同一个文件夹下两个项目之间挪会话只改这个字段、不挪文件。
4. **会话只认记下的项目，不再从文件夹推算。** 没记的、记的项目已被移除的，都不属于任何项目，进「最近」。
   侧栏分组、归档与移除（`projectSessions`）、归档页、读取范围（`projectRootsFor`）、会话间通信（`sessionRoots`）、
   文件树和 @ 菜单的文件夹（`useProjectFolders`）都是这一条。读取范围另要求记下的项目包含 `cwd`，工作树会话不回读
   它出自的那份检出。`folderOwners`、`claimedFolders` 删掉。
5. **先有项目，再有文件夹。** `openWorkspace(path)` 不带 id 就是「这个文件夹」：工作区没有 `projectId`、不写项目
   列表，在这里开的会话不属于任何项目——哪怕这个文件夹正是某个项目的。带 id 才是打开项目、更新「最近打开」。
   新建项目只有「新建项目」弹窗一条路。在同一个文件夹里点开一条无项目会话，工作区也去掉项目，不然下一条会被记错。
6. **「从项目中移除」只清掉 `project`，会话留在原文件夹里跑。** 以前要挪进「不在项目中工作」的临时目录，因为留在
   原地就会照着文件夹再长出一个项目；现在原地不动就已经是无项目会话。
7. **显示的项目名读项目现在的名字**（`projectLabel`）：会话行、命令面板、通知、会话菜单、@ 引用、画廊、归档页。
   不在项目里的会话显示文件夹名。启动恢复和刷新 git 状态时，工作区的名字和 `projectId` 都保留，不退回文件夹名。
8. **属于文件夹的东西仍按文件夹，共用的写明共用。** `.plume/config.json`、项目级钩子、命令、插件、智能体、个性化、
   索引、项目记忆、会话日志目录、工作树、git 状态都是那个文件夹的。设置页按文件夹列的选择每个文件夹一项，名字写成
   共用它的所有项目，按界面语言连起来（`Intl.ListFormat`）：「codex和B」、「codex and B」。
9. **同名又同主文件夹的项目建不出来。** 路径提示到这里也一样，哪儿都分不开，所以新建和编辑弹窗按「保存时会用的
   名字」（留空就是文件夹名）查重（`namesake`），撞上了就在名字下面说明、按钮变灰。只拦这一种：同名不同文件夹、
   同文件夹不同名都照常。
10. **没发出的草稿按项目存。** 项目里是 `new:project:<id>`，单独打开的文件夹是 `new:folder:<path>`（`blankDraftKey`）：
    同一个文件夹的两个项目各有各的半句话；文件夹另起前缀，因为旧项目的 id 就是路径。

## 代价

- **不兼容旧会话。** 旧会话没有 `project`，升级以后全部出现在「最近」里，原来按文件夹归在项目下的要手动挪回去
  （会话菜单「项目」）。没有一次性回写：按文件夹猜归属正是这次要去掉的东西，回写等于把猜测固化进数据。
- **没登记的文件夹不再占一行。** 以前每个打开过的文件夹在侧栏都有自己的分组，现在它们的会话平铺在「最近」里。
- **两个项目共用一个主文件夹时，配置也共用。** 想要按项目各一份，只能把它们放在不同的检出里。

## 没有做的

- **不按项目覆盖文件夹的配置。** `.plume/config.json` 提交在仓库里，是那份代码的；在它上面再叠一层「按项目」的覆盖，
  多出来的是一套谁也看不见的优先级。
- **不在第一次启动时把旧的文件夹分组登记成项目。** 用户明确不要兼容旧数据；而且登记出来的正是「去过的文件夹」，
  和这次的决定相反。

## 什么时候重新看

- 需要两个项目在同一个检出上用不同的配置：要么做按项目的覆盖层，要么让项目可以指定自己的配置文件。
- 又出现「一个文件夹的会话该归谁」这类需求（比如想把某个文件夹里所有会话一起挪进项目）：做成显式的批量操作，
  不要再回到读取时按文件夹推算。
