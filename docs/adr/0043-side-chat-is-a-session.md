# ADR-0043：侧聊是挂在主会话旁边的一个会话

日期：2026-10-11

状态：已采纳；取代 ADR-0040「侧聊不参与」一条里「它的设计就是不碰工作区」的理由，以及 ADR-0025 里
「侧聊不接 `liveModel`」一条。

## 背景

侧聊原来是 core 里单独的一个 `SideChat` 类：自己的循环入口、自己的快照文件（`~/.plume/sidechats/`）、
自己的事件通道（`sidechat:*`）、自己的消息行组件。它只读：能看主会话、能把活排进主会话的队列，
自己不能改文件、不能跑命令。理由是「一个工作区只有一个执行者」。

用下来有两个问题：

- **很多活本来可以交给侧聊做，结果只能送给主会话。** 主会话正在做别的事，侧聊里说清楚了的一件小事
  得排在它后面，或者打断它。
- **两套实现处处不一样。** 渲染是另一套（工具卡片、审批、附件、界面块各自补过一遍），存储是另一套
  （快照、修订号、迟到事件合并），模型跟随、压缩、撤回又各写了一遍。每修主会话一处，侧聊那边就
  欠一处。

「一个工作区只有一个执行者」也早就不成立：后台子代理、人自己的终端都在同一棵树上写。

## 决定

侧聊是一个带 `parentId` 的 `AgentSession`，和主会话共用循环、工具、审批、记录、压缩、持久化。
它和主会话的差别只有这几样（`runtime/side-session.ts`）：

- 每次提问前附上主会话自上次以来的新增（`<main-session>`，写进侧聊自己的记录，前缀稳定）；
  主会话被撤回时整段重读。更早的用 `read_main_chat` 查。
- 三件专用工具：`read_main_chat`、`dispatch_task`、`control_main`。不给浏览器和跨会话工具。
- 一段说明处境的提示词。
- 没定模型和思考强度时每次跟着主会话取。

面板按「父会话 + 面板 id（`sideId`）」认它，第一次提问时才建；关掉标签就删。主会话删除、撤空时
一起删。它不进会话列表，不占活会话名额，不单独回收，不发系统通知，不推给手机。

窗口里，面板用 `SessionScope` 指向这个会话，转录就是主会话的 `Conversation`；侧聊会话只住在
`sessionCache` 里，从不上台。所有入口、多开、标签标题、弹出窗口、分屏隔离、输入框的交互保持原样。

旧的侧聊存档直接丢弃，不迁移。

## 取舍

- **同一棵树上两个执行者。** 侧聊和主会话可能同时改文件。不加锁，靠两层：`edit`/`write` 的读取哈希
  挡住「读过之后被别人改了还照写」；侧聊改了文件，主会话下一轮开头收到一次 `<side-chat-changes>`
  列出路径。提示词也要求侧聊改之前先重读、离主会话正在动的文件远一点。主会话运行时不额外限制侧聊的写操作。
- **审批在侧聊自己那里。** 侧聊要改文件时，审批卡片出现在侧边面板里，不在主列。
- **花销各算各的。** 侧聊的回复记在侧聊会话自己的用量里，不再以 `side-chat` 来源记进主会话；
  用量统计页按 `spend` 表全局汇总，总数不变。
