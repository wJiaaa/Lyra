# 界面国际化

Lyra 的界面语言由 `Settings.uiLocale` 持久化。可选值为 `system`、`zh-CN` 与 `en`。`system` 保存的是跟随系统这个决定，不会把某次检测到的语言写回设置。

## 两个进程

桌面渲染进程的目录在 `packages/desktop/src/i18n/`。`I18nProvider` 解析 BCP 47 系统语言，提供
文案、数字和日期格式化，并在切换时更新 `<html lang>`。切换语言只触发 React 更新，不重载窗口，
因此不会清空草稿、滚动位置或已打开的面板。

Electron 主进程不能依赖渲染进程。原生菜单、文件选择器、系统通知和主进程错误使用主进程自己的
小型文案目录，语言来自同一个 `Settings.uiLocale`；选择 `system` 时读取 `app.getLocale()`。

## 翻译边界

只翻译 Lyra 自己的菜单、按钮、设置、状态和错误说明。以下内容始终保持原文：

- 用户消息与 Agent 回复
- 代码、文件正文、终端输出与 Git diff
- 网页内容、工具输出与外部服务返回的正文
- 用户自定义的模型、供应商、命令、技能和规则名称

## 回退与字体

系统语言按语言族匹配。所有中文地区（含 `zh-Hant`、`zh-TW`、`zh-HK`）都使用简体中文，其他
系统语言回退英语。文案目录缺键时回退简体中文，测试要求两套桌面目录拥有完全相同的键，正常构建
中不会依赖这个回退。

## 新增文案

1. 在 `packages/desktop/src/i18n/messages/zh-CN.ts` 增加语义化 key。
2. 同步更新 `en.ts`，保留变量名与标点含义。
3. 组件通过 `useI18n()` 取 `t()`，不要根据当前语言写条件分支。
4. 运行目录完整性测试，并在真实窗口中检查较长的英文文案是否裁切。

## 单复数与日期

计数变量统一叫 `{n}`。英文里随数量变形的句子写成 `{ one, other }`（`i18n/plural.ts` 用
`Intl.PluralRules` 选形式），只有 zh-CN 源句含 `{n}` 的键允许这样写，中文始终是普通字符串。
一句里有两个计数时，按 `{n}` 那个变形。`i18n.test.ts` 会拦下「`{n}` 后面跟着复数名词却只有一种
写法」的英文词条。

日期和时间不要写死 `"zh-CN"`：组件用 `useI18n().resolvedLocale`，普通函数用 `translate.ts` 的
`activeLocale()`。主进程给人看的提示用 `electron/i18n.ts` 的 `nativeText()`，语言由 `main.ts`
通过 `setInterfaceLocaleSource` 接到设置上；日志保持原文。
