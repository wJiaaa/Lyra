# 对话渲染与阅读位置

对话窗口把消息数据、展示状态、滚动意图区分开，各自按会话保存。最近打开的几个会话保留转录 DOM，切回去是显示而不是重挂。

## 行的身份

`features/conversation/grouping.ts` 将消息转换为展示行，`runKey` 是主会话与子 agent 转录共同使用的身份规则。
一条回复拆成思考行与正文行时，两行必须有不同的 key。思考行属于当前回合，后续回复的思考替换它时保持身份；
正文属于原消息；工具组属于第一个工具调用。主会话再加上 session ID，避免跨会话复用局部组件状态。

不能用展示数组的下标、流式文本长度或 `upTo` 作为身份。重复 key 不只产生警告，还会让 React 在切换后留下
无法正常回收的旧节点，表现为重复思考行、滚动范围增长和跨会话内容残留。

## 高度与挂载成本

默认挂载最近 60 个展示行，用户按需加载更早的历史。问题导航可以直接选择包含目标消息的 60 行窗口，
不用把它与最新回复之间的全部历史挂载起来；窗口前后分别提供继续加载入口。已挂载的行从第一帧使用真实高度，不使用
`content-visibility: auto` 配合估算高度。长回复与单行工具摘要的高度差异很大，200px 占位会在滚动途中
改变 `scrollHeight`，影响滚动条比例与阅读位置。

思考、工具组、整轮过程复用 `ui/layout/Collapse.tsx` 的 grid 高度过渡。首次展开才挂载内容；
工具组打开后保留子树，思考与整轮过程在收起过渡结束后释放子树，减少动态效果时立即释放。
思考正文装在限高（`min(320px, 40vh)`）、自己滚动的框里：还在写时只放纯文本的最后约 16K 字并跟随底部，
用户往上翻就停住跟随和窗口起点；写完换成 Markdown 全文。流式中把整段 Markdown 展开着写，
17 万字的推理会把窗口拖到 4–6 帧，耗时几乎全在样式与布局。
思考行收起时只写标题。字还在到时是「一个说『在想』的词 · 这一段想了几秒」（`正在思考 · 5s`），秒数从
`ThinkingContent.startedAt` 算，和运行指示那个从整轮开始算的钟不是一回事。词随这一段的时长往下换（8、20、40、70、110 秒，
之后每 20 秒轮一个），换词时新词落入、词框宽度平滑过渡；扫光挂在词自己身上。推理后面接上正文或工具调用后是「思考了 N 秒」，
读 `durationMs`，秒数向下取整、和运行指示同一种取法。两个字段都由适配器在思考块开始与结束时记在块上。
不满一秒（多半是中转把整段推理一次吐出来，量到的不是它想了多久）、旧会话、中途断掉的推理，写「思考了一会儿」。
推理内容不上这一行——逐句打在行上的写法在长推理里一直滚动，是整屏最吵的东西；要读推理就点开。

以上都在「显示思考过程」（设置 → 常规，`settings.showThinking`）打开时才有，默认关。关着时只有推理的行在分组时
就拿掉（`withoutThinking`，主会话和子智能体面板同一个），不在画的时候藏：藏起来的行仍然会让只想不做的一轮算成有过程、
让一段活读成「思考 2 次 · …」，点开却什么也没有。夹在一条回复的话中间的推理块也不画。停在推理上的那一行（被停下、
想完没说话）切掉推理留个壳，交付卡片挂在它上面。模型在想的时候，底部运行指示照旧说它在想。
一轮要等第一次推理或工具调用才算有过程；有的模型（经代理的 GPT）不把推理流出来，第一次工具调用之前什么也问不出。
所以人开的、跑着的那一轮从发出就按有过程分（`turnBlocks` 的 `live`），第一句话直接生在 `TurnWork` 里，调工具时
不重挂；跑完没有过程的一轮再退回一句回答。后台结果叫醒的、压缩命令开的一轮不这样分。`TurnWork` 的 key 按开这一轮的
那句话起，里面还空着的时候也不变。
收起中使用 inert/aria-hidden；快速反向切换不能在 transitioncancel 时卸载内容。恢复已打开的组从首帧使用自然高度。
历史转录不重播位移动画；工具折叠与状态指示仍使用既有的过渡。

主会话里有过程（推理或工具）的一轮交给 `TurnWork` 一行行摊开，没有整轮的锚（「已工作 N 秒」），也不整轮收起。
锚试过三种挂法，都删了：跑着就挂，没调工具的一轮也顶着一行，而且跑着时它和底部运行指示说同一个数；等开口调工具才挂，
一出来就是「已工作 39 秒」，那句话也被挪进去重挂一遍；跑完才长出来、把过程收进去（同 ZCode），一整段内容在眼前塌掉，
调了几版动画都生硬。一段段活本来就各自收成一行、说着里面有什么，够了。每一行一个带 key 的盒子，一句话从「最后一行」
变成「过程中的一句」时位置不变、不卸掉重建。后台结果叫醒的一轮、插在一轮中间的送达也一样平铺。

一轮里，同一类连着做的调用合成一行（`grouping.ts` 的 `Step`，类别见 `lib/tool-kinds.ts` 的 `toolCategory`：
编辑、探索、终端、浏览器、网络，其余的工具自成一类）。`bash` 按命令本身分：串起来的每一段都是只读命令
（`rg`、`sed -n`、`git log`……，`lib/shell-reads.ts`）就归探索，其余归终端。命令还在生成时 `arguments` 是空的，这条调用先不画，到齐后直接落进它那一段（`unclassified`）。探索、终端、文件更改三类
挨在一起也合成一段（`joins`）：改失败了读一下再改是「编辑 → 探索 → 编辑」，只按同一类合时一次调用一行，一段修补摊成六七行。
其余几类只和同一类合。外观页从前有三个「工具调用分组」开关能把这三类各自拆开，没人需要，删了。推理跟着它后面那次调用走：接得上就算进这一段，
接不上就去开新的一段；还没等到下一次调用的推理先挂在上一段末尾（`after`），不算次数；后面一直没有调用的就留在那里。前面没有活、
后面也没等到调用的推理自己一行；说了话就另起一段。画出来（`WorkStep`）：

- 一次调用、前面没想过：那一行就是那次调用自己（`ToolCard`），跟在后面的推理在它展开的详情下面。
- 几次调用，或调用前想过：「思考 2 次 · 打开网页 todo.html、操作网页 4 次」，行尾是合计的 +N -M 和失败记号。行首是第一次
  调用的图标；不写类名，「终端 · 执行命令 7 个」把一件事说了两遍。从第一次调用起就说总的，跑着时新的一次接在句尾，
  前面的字不动、框的宽度缓过去（`RollWords` 的 `text`），行尾的箭头和改动数被推过去而不是跳过去。跑着时换成最新那一步、
  跑完再换成总的试过：每来一次调用那一行就跳一下，最后再整句换一遍。「思考 N 次」按先来后到排，句子不会被从前面挤开。
  点开是挂在左侧竖线下的每一次调用和每一段推理。
- 末尾的推理还在写：句尾接一句 `正在思考 · 5s`（`LiveThought`），句子本身不动。推理不另起一行，所以不会有一行冒出来、
  几秒后又被收进上面那一行——旧样子跳的就是这个。

行高锁死在 `FlowRow` 那一个值，跑着时只有字在变。子 agent 面板与侧边聊天仍用工具组
（`ToolGroup`）。规则守在 `test/turn-blocks.test.ts` 与 `test/ui/turn-process.test.ts`，真窗口里的样子见
`e2e/tool-flow-demo.ts`，没有锚、过程跑完照样摊着见 `e2e/turn-no-anchor-demo.ts`。

`preview` 工具放出来的页面是这一轮的结果，不是过程：`runs()` 让它自成一段（`shown`），不收进工具组；
它站在被放出来的位置，夹在两段活中间也不并进哪一行。调用之后同一条回复里还接着想（`[推理, preview, 推理, …]`）时，
这次调用不是结尾的调用、本来留在回复那一行里，而那一行只有推理、算过程，页面就跟着收了进去；现在 `runs()` 把它从那一行里
切出来，照样自成一段，前面那截推理带 `lead`。
失败的那次（页面抛异常被拒）没有页面，照常算过程收起来。规则守在 `test/preview-placement.test.ts`。

## agent 生成的页面

页面写在 `~/.plume/previews/<session>/<id>/`，经 `ly-preview://` 在沙箱 iframe 里内嵌（`PreviewCard`）。
新页面带 `themed`，与回复融为一体：无边框、无卡片底，高度贴合内容（矮的页面最矮 40px，不像带框卡片那样撑到 160px），
上限 720px；旧页面没有这个标记，保留原来的带框卡片。
比上限高的页面折在 720px，底部「展开全部」在原地展开到整页高度（之后跟着页面长短走，和定高一样最多跟 8 次），
右上角「自适应高度」收回（跟随主题的页面平时没有这颗，展开后才出现）；在侧栏打开只走右上角那颗按钮。
侧栏里的 `themed` 页面是顶层文档，左边沿是窗口的，所以在 `html` 上留 24px 28px 的边距；检查窗口照对话里的样子载入，不加。
`preview({ path })` 展示磁盘上已有的 HTML：拷一份进来，不带 `themed`——它是按整页写的，套上对话主题会变样。
例外是本会话 scratch 目录里的文件：只有 agent 往那里写，它是照工具说明写的（不留外边距、不铺底色），当整页放进带框卡片会贴着框边，所以照新页面带 `themed`。

- **主题**：首帧前由地址片段 `#ly-inline&ly-theme=<json>` 带进去，注入脚本（`electron/preview-protocol.ts` 的
  `withPreviewBridge`）写进 `:root`，变量名与值都先清洗；之后的外观切换走 `postMessage`，页面不重载。变量表见
  `features/files/preview-theme.ts`，`--background` 取卡片背后实际画出来的颜色，逐像素对得上。
- **链接**：iframe 内的点击和 `window.open` 转成消息交给宿主，只放行 http/https/mailto，且必须是用户刚在页面里
  操作过（焦点在 iframe、有用户激活）；按 `browser.openLinks` 用内置浏览器或系统浏览器打开，页面本身不跟着走。
- **替人说话**：注入脚本给页面一个 `plume.send(text)`，按钮的点击里调用，文字就作为用户的下一条消息发给 agent
  （`store/say.ts`，界面块的按钮也走它）。门槛和链接一样——焦点在 iframe、有用户激活，所以加载、定时器、改输入都发不出去；
  一张卡 1.5 秒内只算一次。agent 还在跑或队里有话时进队列，和输入框发出的一样。在侧栏里页面是顶层文档，没有对话可说，返回 `false`。
- **记住人调过的**：注入脚本给页面 `plume.state`（上次存的，首次为 `null`）和 `plume.setState(value)`（JSON，最多 16 KiB）。
  卡片按「会话 + 页面」存在 `localStorage`（`store/page-state.ts`，最多 200 页），重新运行、再次打开时经地址片段
  `ly-state=` 在页面脚本之前交回去。人操作过页面时存下的变化（门槛同 `plume.send`）在人下一次说话时附在正文后面，
  格式是 `<page-state page="标题">…</page-state>`，输入框和 `sayFor` 两条路都附，气泡里不显示，每个变化只附一次。
  页面载入时自己存的默认值不算，模型本来就知道。
- **复制为图片**：右上角按钮截的是主窗口里这张卡片此刻的画面（`windows:capture`，`preview-copy.ts`），所以人在页面里
  点出来的状态也在图里；离屏窗口重新载入的是没人碰过的页面。截的是整页：iframe 临时撑到页面自己报的高度，在卡片露出来
  的那块里逐段上移、逐段截，渲染进程拼成一张再进剪贴板；卡片本身不变高，对话不滚动，页面不重载。截的时候藏起卡片自己
  的按钮、去掉圆角和对话边缘的淡出遮罩。上限是 canvas 的 32767 设备像素高。
- 页面里的 `plume.send`、`plume.state`、`plume.tweak` 这组接口不在工具描述里，在 `plume://preview`（`tools/preview-reference.ts`），
  要用时才读：描述跟着桌面端每一次请求走，而写出来的页面很少用到它们。
- **调整设计**：页面用 `plume.tweak({ label, onChange })` 登记滑块、颜色、开关、下拉（`.slider/.color/.toggle/.select(obj, key, …)`，
  每组最多 12 个，最多 12 组），卡片右上角出现「调整设计」，面板画在页面下面（`PreviewTweaks`），用设置页的控件。动一下
  就是一条消息进页面：改 `obj[key]`、调一次 `onChange`，不经过模型。「看原样」切回页面自己的值，「重置」撤掉全部调整；
  只有「按这组设置修改」会说话：气泡里是「调整设计：圆角 18px → 24px」，模型收到 `<design-settings>`，只列改过的项。
  页面报来的控件和面板发回的值都先过 `readTweaks` / `tweakValue`。已知上限：模型按这组设置改，要重写整页 HTML 再发布，
  `preview` 还没有按 id 局部修改。
- **自检**：工具交付前，主进程在离屏窗口（`electron/preview-inspect.ts`）里加载一遍。脚本抛了未捕获异常就不展示，
  异常回给模型去修；其他控制台报错与超高照常展示，只在结果里告诉模型。检查本身失败不影响交付。
- **先看再发**：`check: true` 只检查不展示，结果里带一张截图（默认 720px 宽，`width` 可指定 320–1600；当前主题；一张最多 2160px）和报错、高度。
  结果总会写明按多宽检查的：不写时模型不知道对话多宽，会自己猜一个宽度再多查几次。没截到底时结果给出下一段的
  `from`，带上它再检查就截那一段（`capture` 在缩好窗口之后再 `scrollTo`，内嵌页面的 `overflow:hidden` 挡不住它）。
  从前只截到 720px、只有一种宽度，模型为了看手机宽、宽屏和页面中段结尾，另写了一堆验证页逐份检查，一个请求 26 次；
  放到 2160px 以后，超过这个高度的长页面照样被它按段切成新文件去检查，`from` 补的是这一截。
  满意后 `preview({ id })` 发布，不重发整页 HTML。截图取自同一个离屏窗口的帧（离屏窗口 `capturePage` 是空的），主题由
  渲染进程每次应用外观时经 `setPreviewTheme` 交给主进程。没有这一步时，模型为了看一眼自己的页面，会起本地服务再用
  浏览器工具打开截图，对话里多出一张浏览器卡片。同一轮里先检查再按 id 发布的，页面由检查那一次画到底，发布那一次是
  过程里的一行；这一轮结束了还没发布的检查算过程，跟着收起来；隔了一轮才发布的，页面画在发布那一次上
  （`features/conversation/preview-pages.ts`）。
- **边写边显示**：模型还在写 `preview` 的参数时，卡片位置就是草稿（`PreviewCall` → `PreviewDraft`）。参数文本由
  `lib/partial-json.ts` 读出写到一半的 `html`，画进一个 `srcdoc`、`sandbox="allow-same-origin"`（不给脚本）的框里，
  每 120ms 用 `lib/morph.ts` 把新标记并进去，已有的元素原地不动。样式写完、页面有内容之前就是这次调用本来的那一行工具行，
  标题取写到一半的 `title`；页面画出来以后右上角写着正在写页面 / 脚本和写了多少。写完之后正式页面在草稿下面加载，从草稿的高度起步，淡入盖住草稿后草稿才撤。`check` 那次写的时候
  也画草稿（那是等得最久的一段），写完、检查完都留着，标着「检查过了，还没发布」，等同一轮里的发布到了，正式页面就在
  草稿原地接上；这一轮没发布就结束了，草稿才撤。从前写完就撤，发布要等模型下一轮想完，中间十几秒对话里什么都没有，
  页面再在下面另起一张。草稿的参数自己去 store 读：行只在转录形状变化时重画（`sameRun`），
  拿行给的参数，草稿会停在刚出现的那一刻。工具说明要求按样式 → 结构 → 脚本的顺序写、能写成标记的不靠脚本生成。
- 带主题的页面没有「放到最大」：它按内容定高，放大只会多出空白。
- **定高**：页面每次报高都带上自己被量时的宽度。同一宽度下卡片只跟着变高（按视口排版的页面给多高就报多高，跟着缩
  只是卡片在附和自己）；宽度变了是一次新测量，变矮也跟（`features/files/preview-height.ts`）。之前只许变高时，开侧边
  面板让页面折行变高，收起面板后卡片停在窄时的高度，页面底下留一大片空白。
- **首测**：等页面报高的 1.5 秒从 iframe 加载完才开始算；等满了只是先按 440 露出来，不落定、不记进 `localStorage`，
  之后来的第一次报告照样按首测处理，可以变矮。从前从卡片挂上算起，机器一忙页面还没跑起来就超时，440 被当成量好的
  高度记下来、之后只许变高，卡片锁死在 440（也会盖掉草稿交过来或记住的高度）。上报脚本（`MEASURE_HEIGHT`）在 body
  停在视口上方时直接报 body 自己的盒子，`height: 360px` 的页面首报就是 362，不再先报 256 让卡片缩过头再长回来。
  带框卡片是 `box-content`：高度给页面，1px 边框另算，否则按记住的 362 重开时页面只拿到 360、又报一次 256。

真窗口验证：`e2e/preview-visualizer-demo.ts`；随宽度定高见 `e2e/preview-height-demo.ts`；首测、重开不跳和接着想时页面不进折叠见 `e2e/preview-height-probe.ts`；复制、状态与调整设计见 `e2e/preview-page-tools-demo.ts`。

## 回复里的界面块

回复里的 ```ui 围栏画成原生界面（`features/conversation/interface/`）：统计、图表、表格、标签页、选项、滑块、开关、按钮，
用应用自己的控件和主题，不进 iframe、不跑模型写的脚本。和 `preview` 的分工：要比、要选、要回话的小界面写界面块，
要自己的脚本和样式的整页才用 `preview`。

- **一份语言三处用**：标记、表达式、组件表在 `@plume/core/ui-language`（零依赖，渲染进程和手机端可直接引）。系统提示词里那段
  （`interface` 段，只在加载了 `preview` 时出现）只说有这回事、什么时候用，约 0.7K 字符；语法和组件表在
  `plume://ui`，由组件表生成，写块之前才读——原先整份放在提示词里约 2.8K，每次请求都付，而 3,281 条回复里只有
  9 条用到。桌面端按同一张表读属性，下一轮的问题回报也用同一套检查，并指回 `plume://ui`。
- **边写边长**：一个标签写完整（`>` 到了）才画，写到一半的标签、`{表达式}` 先扣着，数据写到一半的图不会先画成另一张图。
  围栏收口之前整块 `inert`，选项还在长出来时不让点；高度跟着内容过渡长上去，转录贴底跟随才不会每出现一块就被推开一次。
  写到一半的标签由 `parseBlock` 报出名字和将来的父元素（`pending`，属性照样一个不放），那个位置先立一块按组件名
  定大小的占位（`site.ts`）：点阵从中心涟漪展开，一道探针线来回扫过、点亮经过的点，虚线描出外框、四角各一个手柄。
  容器（Card、Row、Grid……）不占位，它们一到就有内容可看。写完时图表和表格先按自己的结构描一遍虚线——外框、
  网格线、柱子、单元格、每行字（`trace.ts`），再由一条线自上而下揭开；其余元素只揭开（`arrive.ts`）。外观参考
  transitions.dev 的 generation 效果，但自己实现，没有它的尺寸标签、计数和坐标读数。只在写的时候有，重开会话直接画；
  减弱动效时占位照样出现但静止，到达不放动画。
- **写完之前不给点**跟着 `Markdown` 的 `Writing`（字还在来、或者还没演完），不跟 `fade`：减弱动效时 `fade`
  不亮，从前界面块因此一直不是 `writing`，选项还在长就点得动。真窗口验证：`e2e/interface-skeleton-probe.ts`。
- **表达式**：自己解析求值（`expression.ts`），只有算术、比较、三元、取字段和一张函数名单；碰不到原型、全局，`==` 按 `===`。
- **状态**：每个带 `name` 的输入是一个变量，`when={…}` 控制显隐。人设过的值按「会话 + 块原文」存在 `localStorage`
  （`interface-state.ts`，最多 200 块），重开还在。没起名字的 `Tabs` 切到哪页也存，但和变量分开放——变量会随 `send`
  发给模型，人在看哪一页不是人说的话。
- **复制**：复制一条带界面块的回复，块换成它画出来的样子（`interface-text.ts`）：数字写成「标签: 值」，表和图写成
  Markdown 表，标签页每页都在，控件写当前的值，按钮不写。按下复制时才算，读的是人这时候设的值。
- **回话**：`<Button send="…">` 的文字作为人的下一条消息发出（`store/say.ts`）；模型收到的正文后面附
  `<interface-values>{…}</interface-values>`，气泡里只显示那句话（`displayText`）。发出去的那句话和那组值跟状态
  存在一起：按钮要说的话和块里的值都没变时，它换成一行「✓ 已发送」，按不动；改了任何一个值就回来。
- **写错了告诉模型**：不认识的组件、属性，类型不对、读了没声明的变量、调了名单外的函数，以及忘了 ```` ```ui ````
  围栏、组件直接写在正文里（行首就是名单上的组件名，正文按文字显示了出来），在下一条人说的话后面附一段
  `<env>`（`ui-language/notes.ts`）。漏围栏的不替它画：正文里引用一段 `<Card>` 写法时会被当成控件。请求拼装时按历史算出，不进日志，同一份历史每次同样的字节，不打断前缀缓存。
- 画的时候抛异常，退回成那段源码的代码块。
- **侧边聊天**：它本身是会话，转录就是 `Conversation`，块的画法、`send`（`sayFor` 按会话说，正在答就排队）和
  状态的 key（会话 id）都和主会话一样，自然落在侧边聊天自己身上。
- **手机端只读**（`mobile/src/Interface.tsx`）：排版、文字、数字、表、图照样画，标签页能切；输入类控件只写出当前值，
  按钮不画，块底下一行说明回电脑上操作——手机发消息还带不上 `displayText` 和块里的值。读块的规则经
  `@plume/client-runtime/ui-language` 转给手机，和桌面同一份（图表怎么读数据在 `ui-language/chart.ts`）。没有 SVG，
  一个序列的图画成横条，多序列或超过 24 个点退成表。值是块的初值，桌面上改过的存在那台电脑的窗口里。

真窗口验证：`e2e/interface-block-demo.ts`（`THEME=dark` 再跑一遍深色）；手机端 `e2e/mobile-interface-probe.ts`；侧边聊天
`e2e/sidechat-interface-probe.ts`。

正在推进的只有一段：一轮还在跑、而它是这一轮最后一行的那一段（`WorkStep` 的 `live`），任何时候最多一处在扫。断线记录（`HiccupRow`）
只有收了场的才算过程：还在等重试的那条是此刻的倒计时，放弃了的那条是这一轮的最后一句、带着「继续」，两者都不并进
哪一段活——并进去的话，失败的那一轮那一段收着时连「继续」都找不到。

## 点击与加载

侧栏行的选中必须落在点击这一帧。`previewSession` 只写 `pendingSessionId`，不用
`flushSync`——连点时强迫同步提交会把主线程锁死。转录的替换走同一拍的 `openSession`，
也不用 `flushSync`。

每一行自己问「我是不是亮的」。点一下只醒被点的那一行和正在离开的那一行。
分屏树里那片正在被替换的叶子，在 `show()` 改掉它之前仍写着上一个 id；那不是「另一格还开着」，
不能再点亮。`pendingSessionId` 清掉的同一拍就把叶子换掉，否则旧行会闪一下激活底。

每一次按下先亮行，同一拍替换分屏叶子和转录。大图是文件，不是会话正文：新写入
就把像素停到 `session-media`，会话库与 IPC 只留 `media` 指针。文件按内容命名，几条会话可以
指着同一张；删会话时只删已经没有记录指着的那些。
窗口用普通 `<img src="ly-media://m/…" loading="lazy">`，由浏览器按视口取图。
已打开过的会话留在 `RetainedViews` 里。分屏格子按树路径挂载。磁盘上序号没变时
不再把整份转录克隆进渲染进程。连点不再空等 360ms。磁盘读取仍然合并成最后
那个 id。较新的点击用 `selectionEpoch` 作废还没提交的那一次。

## 两种缓存

- `store/session-slice.ts` 与 `session-read.ts` 保存最多 12 份已读会话，恢复消息、工具结果、任务、审批和运行状态。
  最近访问的会话会更新淘汰顺序。重新读取相同序号的已完成日志时复用消息对象；已缓存会话在读取期间到达的事件
  不会被较旧的刷新结果覆盖。后台消息、工具、审批和结束事件直接折叠进已读缓存，标记待校准，
  不删除缓存。重新打开立即显示已更新的内容，再读取磁盘校准。冷读期间记录事件，保留磁盘历史前缀，
  合并期间到达的消息；两种读取路径都恢复子任务和运行能力。运行中会话的主进程转录只有已落盘的消息，
  校准时保留屏幕上还在流的回复和插进这一轮、尚未被循环取走的消息（`lib/transcript.ts` 的
  `withInFlight`）；主进程转录已经越过屏幕时不保留，等事件补齐，避免同一条出现两次。
- `features/conversation/view-state.ts` 单独保存最多 12 个会话的历史加载范围及思考、工具组、工具详情的展开选择，
  不持有消息数据或 DOM。它独立于消息缓存的更新与校准。

串行读取队列只合并磁盘读取请求，不能再次调用会话选择逻辑，否则会将用户刚恢复的状态清空第二次。
流式更新在离开会话前刷新，延迟到下一帧执行的回调也必须核对 session ID。

## 阅读位置

`ui/scroll/useFollowBottom.ts` 分别记录跟随末尾、主动回看、正在返回末尾三种意图。
保存的偏移只在对应会话的真实内容可测量后恢复；加载占位与隐藏面板不能覆盖保存的位置。
会话切换会取消旧的滚动动画与待执行的写入。滚轮、触摸、键盘及自定义滚动条拖动均参与意图判断。

跟随末尾时，输出中一屏以内的长高用弹簧追，但最多落后 40px（`LAG_MAX`）：超出的部分在长高的同一帧写掉。
界面块的元素、工具卡是整块到的，从前整段慢慢追，运行行被压到视口下沿以下 129px、21 帧；现在最深 39px。
`e2e/follow-chunk-probe.ts` 逐帧量画出来的那一帧离底多少。

`Scroller` 在内容或视口尺寸变化时先执行跟随逻辑，再测量滚动条。浏览器原生 scroll anchoring
负责同一会话中上方内容折叠、加载历史等情况；它不能替代切换会话时的显式恢复。

问题导航只包括真实用户消息，合成提示不占刻度。相同文本仍以各自消息位置定位，图片消息有文本替代。
刻度支持鼠标点击、键盘聚焦、悬停预览与当前位置提示。当前窗口内跳转使用 420ms 滚动过渡；
需要更换历史窗口时先挂载目标，再在 layout effect 中定位，避免先画一帧错误位置。
减少动态效果时直接定位；新输入与离开会话会取消旧动画。

## 首次提交与身份

新对话草稿在提交前不写盘。提交后，主进程先创建 UUID、从首条消息生成临时标题并持久化消息，
返回侧栏条目后才初始化工作区、MCP 和模型。`pendingPrompt` 表示尚未交给模型的已存消息，
`resumePendingPrompt` 单飞消费它，不再追加一份相同用户消息。

渲染器以选择代次区分不同草稿。同一草稿的创建请求合并；较早草稿的异步创建结果只更新自身条目和缓存，
不能抢走新选择。标题始终是标签，重命名、归档、删除、缓存与草稿均按 ID 隔离。
乐观用户消息同时记录所属 session ID 与原消息引用。前台和缓存中的确认都必须匹配这两个条件；
尚未创建会话的草稿 ID 为 `null`，只能由创建结果接管，不能匹配任意已存在会话的事件。
初始化过程中停止会清除待提交标记；初始化晚到也不能重新启动模型。
worktree 只改变执行目录，不改变已创建的会话 ID 和日志归属。要不要 worktree 按会话定：输入框上的开关随首条消息
传下去（`initial.worktree`），设置里的开关只是它的默认值；建好之后 `SessionMeta.worktree` 记下它出自哪个项目，
侧栏、归档、项目菜单都按这个项目归组（`sessionHome`），从它开的新会话回到这个项目。见 ADR-0048。
删除、归档会话时收走它干净的工作树目录（分支全在基分支里就一起删），取消归档或再用起来时在原路径检出回来；输入框上
工作树会话的 chip 说领先落后，点开能合回基分支、从基分支同步（`electron/worktree-lifecycle.ts`、`worktree-merge.ts`）。
建不成工作树的原因记在 `SessionMeta.worktreeError` 上，输入框上一直有个提醒。见 ADR-0050。

## 页面保留

非会话页面使用 React Activity 和有界 LRU 保留。主页面、Git Tab、设置分区与扩展 Tab 分别管理
自己的访问范围；隐藏页面暂停 effects。`Scroller` 在隐藏前保存原生偏移、恢复显示前还原，
避免浏览器在隐藏时将 `scrollTop` 归零。页面入场只做短暂透明度变化，不移动内容。
空数据与未完成读取使用不同状态；缓存回访不经过 Empty，真正慢的首次读取才显示骨架。
冷会话在 `messages` 仍为空且 `loadingSession` 为真时只画 `ConversationSkeleton`，不看
`meta.messageCount`——那条计数会在数据到达前就把空的 `Conversation` 挂上去。IPC 快照会裁掉
超大工具结果和正文，完整内容留在会话日志里。转录行距由列表容器的 `gap-2.5` 统一给出，
子行不再各自声明 `mb-2.5`。

## 提问、队列与取消清单

提问/审批卡片在 composer 上方正常文档流中占位，长内容用公共 Scroller，底部操作始终可见。
收起只隐藏正文，不卸载答案草稿。推荐标记不等于默认答案；单多选在确认后提交。skip 无默认时明确表示未回答，
只有显式 defaultOptionIndex 才产生默认答案。Full Access 免除操作权限审批，不替用户回答业务问题。

队列移除项在本次 render 就保留原 key，按批次独立清理退场计时器；最后一行的高度、边框和 margin 同时收缩。
撤回编辑时 textarea 从原 px 高度过渡到目标 px 高度。排队发送按钮保留 DOM、宽度过渡，隐藏时 inert；
发送/停止/继续共用一个按钮，图标渐变，不因换形态重建按钮。

`clearsTaskPlan` 是日志中合成用户消息的明确取消标记。前台事件、后台缓存和历史投影统一清空 Todo；
取消前 runtime 等待在途工具结束，防止迟到的 todo_write 恢复已取消的清单。
