# 分屏、工具拖动与独立窗口

2026-09-19。依据用户提供的 `录屏2026-09-19 11.55.35.mov`（63.233 秒、3016×1824、60 fps）和本机 Claude 桌面应用的实际操作整理。研究只观察界面，不使用 Claude 源码。以下区分观察事实、Plume 实现及尚未证实的范围，不能把代码参数当作竞品测量结果。

> 2026-09-24 更新：R01 这时写的是「会话外层分屏、工具在会话里」，但实现里仍保留了一层窗口级 dock，套在整个分屏外面。分屏时它横跨所有屏，回到单屏时又和那一屏自己的 dock 叠在一起，这就是任务面板独占右侧、浏览器嵌在标题栏下两个问题的来源。这一层已经删除，见 [ADR-0023](../adr/0023-containers-belong-to-sessions.md)：每一屏一个 `DockView`，单屏是只有一屏的分屏，窗口本身没有面板。下文凡是提到「窗口 dock」的地方，都指改之前的实现。

> 2026-10-07 更新：会话内的面板只剩标签页一种排法——对话右侧一栏，每个面板一个标签。R09–R11 的面板排布、
> R12–R16 的移动把手、拖动与键盘挪格，以及 R18 里的把手，都随分栏排法删除了；下表这几行留作当时的记录。

## Plume 实现清单

### 布局与内容寿命

- [x] 单会话和多会话都经过相同的 `DockView`（每屏一个）；第一次打开工具不替换聊天输入框。
- [x] 各工具是平面的 keyed DOM；布局树只决定几何，不决定嵌套 React 结构。
- [x] 工具和会话的实际 DOM 顺序保持稳定。仅 React key 不足以保护 Electron webview，移动祖先 DOM 仍会重建 guest。
- [x] 增加、关闭相邻会话、整会话换位时保留浏览器 guest id、页面 `performance.timeOrigin` 和表单文本。
- [x] 切标签只换画哪一个，其余标签隐藏但不卸载；开关面板不重建对话。
- [x] 每个会话自己的标签顺序存入 localStorage，刷新恢复；右侧一栏的宽度全窗口一份。
- [x] 窄聊天标题栏收起快捷工具按钮，保留菜单及关闭入口。

### 标签、缩放与键盘

- [x] 新开的面板排在最后一个标签；已经开着的面板只切到它。
- [x] 对话与右侧一栏之间的分隔条拖动调整比例，双击均分，键盘方向调整，Home 均分。
- [x] 两者并排放不下时上下排；两条轴都放不下时标签保住下限、对话被盖住一截，不压碎正文。
- [x] 全屏是「右侧一栏铺满」：切标签、新开标签都保持全屏，关掉最后一个面板才退出，不影响另一会话。

### 窗口交接与状态隔离

- [x] A/B 会话 Browser 只绘制自己的 tabs，各自保留选中项。
- [x] 每屏承载自己会话的页（面板关着也不卸载，开关不重载）；不在任何屏上的 wanted/后台页由在屏最久的那一屏隐藏承载，已由独立窗承载的页一律让出。
- [x] 弹出前同步提交页面承载权，防止主窗和独立窗同时 attach 同一 tab。
- [x] 创建窗口失败时恢复原 dock；同一 scope/kind 再次打开激活已有窗口。
- [x] 浏览器导航及新增页面状态广播给应用窗口，包括暂时没有 guest 的独立窗。
- [x] 浏览器 IPC 校验实际登记的应用窗口和主 frame，不再依赖易变的键盘焦点。
- [x] 终端每会话独立选中 pty，新会话不自动抢用另一会话正在显示的 shell。
- [x] 终端 pending command 由所属会话消费一次；弹出与返回恢复相同 pty。
- [x] 弹出记录包含完整原树、离开后的树及原来是第几个标签。
- [x] 剩余树没变时精确恢复原树；期间用户改变了标签时回到原来的标签位置，不覆盖新布局。旧版本写下的记录没有标签位置，排到最后。
- [x] 原会话已不在屏上时，收回先把它请回屏上再放回面板（请不回来就写进它存着的布局）；关闭独立窗清理回家记录。
- [x] 应用退出时还没收回的面板，重启时放回原会话的标签里，不自己开窗口。
- [x] 会话窗和工具窗都有置顶开关，仅操作请求方 native BrowserWindow。
- [x] 新菜单及置顶文案覆盖七种界面语言。

## 几何参数与交互事务

以下是 **Plume 的实现值**，不是 Claude 内部参数：

| 参数 | 值 |
| --- | --- |
| 会话分屏数量上限 | 4，沿用 Plume 现有上限 |
| 外层会话 tile 与聊天容器下限 | 420×260 CSS px |
| 工具容器下限 | 300×150 CSS px |
| 会话 dock | 可读下限同上；compact 窄窗口布局仍采用单面板切换 |
| 分隔条命中宽度 | 9 CSS px |
| 键盘分隔条步长 | 2%；Shift 为四倍 |
| 状态 / 几何过渡 | 150 / 220 ms，使用 Plume motion tokens |

弹出快照不是强行回滚：只有当前剩余树与离开快照完全一致才恢复完整树，否则按记下的标签位置放回。新窗创建、源 guest 释放、原位恢复分别有明确的状态边界。

### 最小尺寸

面板不再因为放不下被自动弹成独立窗口：对话和当前标签并排放不下就上下排，两条轴都放不下时标签保住下限、对话被盖住一截（见 `test/dock-overlap.test.ts`）。外层会话分屏仍按 420 px 下限检查，放不下的会话转入独立窗口。

保存比例与显示比例分开。旧布局的 8%/92% 比例仍会在显示时保护 420 px 下限；放大后可以恢复用户比例。

收回是人按下的「收回」，总是落地：回到原来的标签位置。创建窗口失败的回滚同样按标签位置放回，期间打开的其他面板不被旧快照覆盖。

### 文件窗口交接

文件面板弹出时，主进程按真实来源窗口托管当前路径及换行/源码显示偏好。一格文件面板只看一个文件（多开文件是 dock 顶上的多个标签 `file`、`file:<id>`），协议里的 `tabs` 只剩这一个文件。目的窗口重新经过 `files.read` 读取磁盘内容与权限，跨窗口消息不能替代文件访问边界。

独立窗口中的改动（当前文件、换行、源码显示）通过版本号确认；旧版本请求返回最新状态，只合并本次改动。源窗口把文件打开到已弹出的那一格时复用已有文件窗口并切到该文件。收回时把该窗口的文件放回它原来那一格，不影响源窗口其他文件标签。普通原生关闭也要等待最后一次改动确认。

## 已定位的根因

| 现象 | 根因 | 修复与证据 |
| --- | --- | --- |
| 打开工具或提起最后一个工具后内容重建 | 单叶分支返回另一种 DOM | 始终平面 keyed 列表；UI 测试在修前实际跑红 |
| 拖动卡片偏移一整个 tile | contain-layout/paint 改变 fixed containing block | Popover 顶层；修前目标 x=272 实际 x=544 |
| 拖动后浏览器表单丢失，即使 DOM identity 没变 | React 重排父节点，Electron guest 被销毁 | 固定真实 DOM 顺序；测 guest id、timeOrigin、文本 |
| 预览时持久化布局缺少被拖工具 | preview 共用了持久化 write | 分开预览与提交；修前持久化测试实际跑红 |
| A/B 会话显示相同浏览器页与终端 | 读取全局 activeSessionId/active terminal | 使用 SessionScope，分别保存选择 |
| 隐藏主窗与两个 tile 重复挂载同一个网页 | 缓存策略不知道其他容器承载权 | 主窗 4 个重复 guest → 每 tab 1 个；真实窗口红绿验证 |
| 浏览器独立窗偶发空白或初始化失败 | IPC 只信任当时获得焦点的窗口 | 登记窗口 + 主 frame 校验；无焦点也可同步 |
| 从深层布局返回后宽度改变 | Home 只记邻居，丢了祖先分支比例 | 完整树快照；380.09375 px 弹出后仍为 380.09375 px |
| 失焦后卡片停在半空 | 取消仍依赖后台节流的动画帧 | 失焦/resize 直接结束浮动状态 |
| 聊天被压成 72 px、正文只有 24 px | 内层分屏使用了低于文字可读宽度的独立下限 | 统一 420/300 px；真窗口正文最低 372 px，输入框 370 px |
| 初次恢复旧布局没有自动弹出溢出工具 | opacity=0 的入场帧被误判为不可见，动画结束后不重新执行 | 按 inert/visibility 判断，监听保留会话重新激活 |
| 工具已弹出却在原窗重新出现 | 最后工具移走后删除内存树，hydrate 从尚未清除的存储读回旧树 | 内存保留已加载的空会话树；回归用例实际先红后绿 |
| 空间不足的工具重启后消失 | 孤儿恢复把尺寸不足误判为会话不存在，超时删除记录 | 已测量目的地不足时重新创建工具窗口并保留原记录 |
| 弹出终端失焦后输出缺行 | 主进程只给当前焦点窗口发送 terminal:data | 应用窗口广播；连接按 renderer 与 attach epoch 管理 |

## 截图保存与连续捕获

截图下载先写入当前设置指定的目录，完成后才尝试可选的剪贴板复制。系统剪贴板异常不能阻断已授权的文件保存。下载时读取主进程最新设置，不使用开始截图时的旧目录。失败保留完整选区并显示文件系统错误，成功 toast 只显示「已保存」，不显示路径。成功提示共用固定 144×144 px 的正方形容器，勾号与文字居中；失败提示按错误内容展开。

未指定下载目录时使用 Electron 的 `app.getPath("desktop")`，因此遵循系统桌面位置（包括 Windows 重定向的桌面）。截图工具栏只有一个下载箭头，负责写文件；右侧「完成」使用勾号，按原设置交付剪贴板和对话。此前「完成」因为不能覆盖原图而借用了下载箭头，导致同一栏两个下载图标中，醒目的白底按钮不写下载目录、也没有保存 toast；接口测试不会发现这种图标与动作的错配。

截图浮层是复用窗口，下载锁、异步回包与离场计时器都必须归属于捕获编号。开始下一次截图、隐藏或卸载后，旧请求不能锁住新下载，也不能把新选区关闭。

`e2e/screenshot-download.test.ts` 检查中文带空格路径、切换目录、剪贴板异常以及不可写路径，已加入 Windows UI CI。它还通过真实鼠标点击设置页的「立即截屏」、框选和可见下载箭头，测量默认桌面与目录选择后的 PNG、保存提示的透明度和尺寸，以及失败原选区重试。屏幕获取边界只返回一次性 Plume 设置窗口的真实截图 fixture；其后的启动、捕获编号、指针事件、裁图、IPC、写盘和 toast 都走产品代码。系统桌面通过 `app.setPath` 指向隔离测试目录，避免测试文件留在用户桌面。

图标回归在 0.9.16 正式包上实测失败（下载箭头对应「下载截图」和「完成」两个动作），修复后 macOS 真实窗口检查 6/6 通过，录像为桌面 `Plume截图下载修复测试/2026-09-19T11-29-19.169Z_截图下载_6of6.mp4`。组件测试同样先红后绿，确保图片预览中的「保存副本」仍保留下载图标。

## 边界与未证实项

- 本机 native 验证为 macOS。Windows/Linux 的原生全屏、标题栏、置顶需要对应平台复验。
- 没有证据可声称 Claude 的像素、动画曲线、所有极端排列和未知上限已逐一相同；Plume 保留自己的主题与字体 tokens。
- 同一窗口内切标签、开关面板保持浏览器执行上下文。跨 native 窗口弹出会重新创建 webview，保留 URL/tab 归属；任意网页的内存状态和导航历史不保证完整迁移。
- 工具不因指针越过会话边界而转移所有权；跨会话松手撤回。不同会话可以各自打开工具。
- 终端每格一个 shell，按「屏 + 格」记住选中项；再开一格起新 shell，关掉后开的那格会结束它的 shell。
- 文件预览按「屏 + 格」各存各的文件（`store/openFile.ts` 的 `fileSlot`），只在内存里；重启后后开的文件标签不恢复。跨窗口交接保留当前文件与显示偏好；CodeMirror 的选区与滚动位置未跨 renderer 迁移。
- 侧栏拖出整个 native 窗口自动创建新窗口并未据此实现；New window 通过明确菜单入口创建。
