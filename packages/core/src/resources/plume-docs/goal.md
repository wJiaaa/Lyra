# 持续目标 /goal：怎么定、怎么判定做到、怎么取消

平时 Plume 回答完一轮就停。定了持续目标后，每一轮结束都会单独判一次「目标做到没有」，没做到就自动接着做，直到做到、做不到或撞上上限。适合「把 CI 修绿」「等这个 PR 合进去」这类要一个结果、而不是一次回答的事。

## 定目标

在输入框里输入 `/goal 目标`，比如 `/goal 把 CI 修绿`，回车。

- 目标那句话会作为你说的话进入对话，Plume 立刻开始做；如果它正在忙，这句话插进当前这一轮。
- 需要一个已经开始的对话。空白新对话里先发一句话。
- 不接收附件。
- 一个对话只有一个目标。再发一次 `/goal 新目标` 会替换掉旧的，判定次数从零算起。

## 状态条

定了目标后，输入框旁显示项目和分支的那一条里会多出一行：目标原文、当前状态，以及「第 n/50 次判定」。状态有：

- 在做 / 在判定：正在干活，或正在判断做到没有。
- 在等，m:ss 后再看：在等外部的事（任务还在跑、回复还没来），倒计时结束后自动再看。
- 已达成、走不到、已停下：原因 —— 这三种是结果，Plume 不会再自己续，状态条留着让你看结果。

点状态条右侧的「取消目标」可以随时取消；结果状态下点它就是把这一行收起。也可以发一条不带内容的 `/goal` 来取消。

## 怎么判定做到没有

每一轮正常结束、而且排队的消息都处理完以后，Plume 用一次单独的小请求做判定。它只看目标、任务清单、这一轮调用了哪些工具和最后一条回复，不看整段历史。结论有五种：

- 达成：回复里能看到结果（比如检查通过），光说「做完了」不算。对话里会出现「目标已达成」的提示。
- 走不到：缺了只有你能给的东西（一个决定、一项权限、目标本身有矛盾）。提示里写明缺什么。
- 有进展：接着做下一轮。
- 没进展：要求它换个办法接着做。
- 在等：先睡一会儿再叫醒它，间隔依次是 30 秒、1 分钟、2 分钟、5 分钟、10 分钟，之后每次 30 分钟；中间有了进展就从 30 秒重新算。

判定可能出错，最贵的一种是误判成「达成」。所以达成后最好自己核对一下结果。

## 什么时候会停下来等你

下面任何一种情况发生，目标都会变成「已停下」，对话里出现提示并写明原因：

- 判定次数用完了（最多 50 次）
- 连着几次没有进展（连续 5 次）
- 裁判连着几次读不出结论（连续 3 次）
- 已停止：你按了停止
- 这一轮出错了：模型服务报错（自动重试用完，或是重试也没用的错误，比如请求被拒的 400），或撞上了步数、重复检测等上限。重试中途恢复了不算

停下或结束后，Plume 不会因为你再说话而自动续上目标。想继续，重新发 `/goal 目标`。

## 其他

- 目标记在这个对话上。应用关掉再打开，正在等的目标会按原来的时间接着等。
- 判定用的模型在「设置 › 智能体」页「会话」一组的 goal 一行里选（说明是「判定持续目标做到没有」），默认跟随主会话。每次判定的用量算在这个对话里。
- 目标进行中，每一轮结束不发系统通知。达成、走不到、停下时，如果 Plume 窗口不在前台，会发一条系统通知，点它回到这个对话。
