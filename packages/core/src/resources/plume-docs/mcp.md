# MCP 服务器：怎么添加、登录、配置写在哪、连不上怎么查

MCP 服务给 Plume 带来新工具（搜索、数据库、浏览器……），有的还带提示词。支持三种连接方式：stdio（本机起一个进程）、Streamable HTTP、SSE。

## 在哪添加

管理页在「设置 › 插件」的「MCP」标签。

- **从市场装**：侧栏「插件」打开插件市场，切到「MCP」，进详情点「安装」。装好的服务**默认关闭**：先在「密钥与配置」里填好它要的值，再打开开关。
- **手动加**：「设置 › 插件」右上角「添加 › 添加 MCP 服务器」，或在「MCP」标签右侧 ⋯ 里选「添加 stdio 服务」「添加 HTTP 服务」。会新建一张卡片，鼠标移到卡片上点滑杆图标（「启动方式与环境变量」）展开，填：
  - stdio：「命令」（如 `npx`）、「参数」（空格分隔）、「环境变量」
  - HTTP：「URL」，「传输方式」选 Streamable HTTP 或 SSE

同一个展开区里还有两个开关：「信任它的只读声明」（见下文「审批」）和「常驻」（见下文「工具多时」）。改动是逐字自动保存的，没有保存按钮。

## 配置存在哪

只有一处：用户级的 `~/.plume/settings.json` 里的 `mcpServers`，对所有项目生效。**没有项目级 MCP**：项目里 `.plume/config.json` 写的 `mcpServers` 会被忽略（会话里提示一句「被忽略了」）；项目根目录的 `.mcp.json` 也不读，要用就在设置页手动加一遍。

手改文件时，`mcpServers` 是一个数组：

```json
{
  "mcpServers": [
    { "id": "fs", "name": "Filesystem", "transport": "stdio", "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/me/code"], "enabled": true },
    { "id": "docs", "name": "Docs", "transport": "http", "url": "https://mcp.example.com/mcp",
      "headers": { "Authorization": "Bearer ${DOCS_TOKEN}" }, "enabled": true, "trustReadOnly": true, "pinned": true }
  ]
}
```

- `transport` 取 `stdio`、`http`、`sse`。设置页没有请求头的编辑框，要带鉴权头只能这样手写。`trustReadOnly`、`pinned` 对应上面那两个开关，可不写。
- 参数、环境变量的值、URL、请求头里都可以写 `${名字}` 空位，连接时先取这台服务自己「环境变量」里的值，没有再取同名的环境变量（shell 启动文件里 `export` 过的也算）。
- 名字像密钥的环境变量（含 KEY、TOKEN、SECRET、PASSWORD 等）加密保存在本机，`settings.json` 里只留 `${名字}`。
- 从市场装的服务，文件放在 `~/.plume/mcp/<名字>/`。

新建的会话按最新配置连接；进行中的会话可能还拿着之前的连接，改完配置后新开一个会话最稳妥。

## 需要登录的远程服务器（OAuth）

HTTP / SSE 服务要求 OAuth 登录、而你没在请求头里配 `Authorization` 时，卡片显示「需要登录」和「登录」按钮。点「登录」会在浏览器里打开它的授权页，授权完自动回来（最多等 5 分钟），已打开的会话会重新连上它。登录后卡片上写「已通过 OAuth 登录，令牌加密保存在本机。」，旁边是「退出登录」。令牌快过期时自动续；续不上、或服务器要求更大的权限时，回到「需要登录」，再登录一次即可。改了 URL 或删除这台服务器，登录记录一并作废。登录前它的工具用不了。

## 怎么看连没连上

卡片名字下方的状态：

- 绿点「N 个工具」：已连上，点这几个字展开工具列表。
- 「缺少密钥」：有 `${名字}` 空位没值，服务**不会启动**。卡片里列出缺哪几项，填好失焦即保存。
- 「需要登录」：见上一节。
- 「连接中…」：正在启动。「重连中（第 n 次）」：断线后在自动重连，最多 8 次（间隔从 0.5 秒翻倍到 30 秒）。
- 红点「连接失败」：卡片上写着具体报错，stdio 服务还附「服务器 stderr 的最后几行」；旁边有「重新连接」按钮（⋯ 菜单里也有）。
- 「未启用」：开关是关的。

有当前会话时显示的是这个会话手上的连接；没有会话时，设置页会临时连一次来查状态。连接失败时，对话里也会提示一次「MCP 服务器「…」没有连上：…」。

## 常见连不上的原因

- **命令找不到**：`npx`、`uvx`、`node` 等不在 PATH 上。macOS 和 Linux 上 Plume 用登录 shell 的环境启动服务，终端里能跑通的命令一般就能用；不行就在「命令」里写完整路径。
- **超时**：见下一节的时限；第一次超时可以点「重新连接」再试。
- **URL 或传输方式不对**：服务说的是 SSE 就要选 SSE，反过来也一样。
- **参数里有空格**：「参数」按空格切分，带空格的路径要去 `settings.json` 里把 `args` 写成数组。

## 连接要多久、会不会拖住对话

- 打开会话不等 MCP。第一轮开始前，还在启动的服务器最多再等 5 秒；没赶上的连好后从下一轮起可用。服务器中途改了工具列表，也从下一轮起生效。
- 连接和列工具各限 30 秒；用 `npx`、`uvx` 这类包管理器第一次启动时会先下载，放宽到 180 秒。
- 一次工具调用 5 分钟既没结果也没进度才算超时；服务器报进度的话，进度显示在工具卡片上，每报一次重新计时。按停止会通知服务器取消。
- 结果特别长时，模型先看到开头和结尾，全文存成文件供它读回；超过 200 KiB 的图片卡片上照常显示，模型拿到的是文件路径。

## 工具名、审批、计划模式

- 工具以 `mcp__<服务 id>__<工具名>` 交给模型。名字超过 64 个字符、含字母数字 `_` `-` 以外的字符（会换成 `_`），或和别的服务器、内置工具撞名时，改成截短加 8 位哈希的名字。同一个工具每次得到同一个名字，所以「以后不再问」一直有效。
- 审批：服务器声明会删除或覆盖数据的工具，「帮我批准」下也要你点头；声明只读的，只有打开了这台服务器的「信任它的只读声明」才不再逐次确认。详见 `plume://permissions`。
- 计划模式只放行服务器声明为只读的工具，见 `plume://plan-mode`。

## 提示词与表单

- **提示词**：服务器带的提示词出现在 `/` 菜单的「MCP 提示词」一组，名字是 `/mcp__<服务 id>__<提示词名>`，用法见 `plume://commands`。
- **表单**：服务器在工具调用中途要你补信息时，会弹出「<服务名> 需要你填写」的表单，可以「提交」「拒绝提供」或「取消」。「完全访问」也照样弹——它免的是操作审批，不替你填答案。30 分钟没人回应按取消处理。

## 工具多时：按需加载

没设「常驻」的 MCP 工具，说明合计超过约 3,000 token（大致三台普通服务器）时，模型不再一次看到全部工具，而是看到一份每台服务器一行的目录，要用时先搜（`mcp_search`）、再调用（`mcp_call`）。对话里显示的是一张搜索卡片和真正被调用的那个工具的卡片，审批和计划模式的限制与直接调用一样。同一个对话切到这种方式后就不再切回。天天要用的服务器打开「常驻」，它的工具会每轮直接给模型。

## 删除

卡片右侧 ⋯：手动加的显示「删除」，只删这条配置；从市场装的显示「卸载」，会连同 `~/.plume/mcp/` 下它的目录一起删掉，你在设置页改过的参数也会一并清掉。
