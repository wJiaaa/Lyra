# 上下文与压缩：上下文满了会怎样、什么时候自动压缩、怎么手动压缩、压缩后丢什么

## 看上下文用了多少

输入框里有一个上下文用量指示，悬停显示「上下文占用 N%」，点开能看到「上下文窗口用量」的明细：对话消息、内置工具、MCP 工具、技能目录、系统提示词、项目指令等各占多少，以及剩余空间。占用到 80% 时会提示「接近上限，较早的消息会被自动摘要压缩。开新对话可以拿回全部窗口。」

上限取的是这个模型在「设置 › 模型设置 › 编辑模型」里的「上下文窗口」。这个值填得不对，压缩时机也会跟着不对。

## 自动压缩什么时候触发

- 用量达到上下文窗口的 **90%** 时触发。窗口很小的模型会提前一些，给摘要留出位置。
- 每次请求模型之前检查一次；桌面端主会话在一轮结束后也会检查，趁缓存还热时先压掉。
- 先做不花钱的一步：清掉空结果、被后来的读取覆盖的旧结果，裁短过长的工具输出。这样已经够了就不再写摘要。
- 不够时，用**当前会话的模型**把较早的对话写成一份摘要（没有单独的压缩模型可选）。过程中会显示「自动压缩」和「正在生成摘要…」，完成后显示「N → M 条消息」。
- 摘要请求失败时，改在本地整理（「摘要失败，正在本地整理…」）；再不行，就直接丢掉最早的消息，并告诉模型前面有内容被删掉了。
- 模型服务因为上下文超长拒收请求时，会提示「上下文超出了模型的上限，正在压缩历史后重试。」

## 手动压缩

- 在输入框输入 `/compact` 发送；后面可以跟一句希望摘要保留什么，例如 `/compact 保留数据库迁移的讨论`。也可以用 `@compact`（「压缩上下文」）。
- 手动压缩不等窗口快满，现在就整理较早的对话。如果没有可整理的，会提示「已经够紧凑了，这次压缩不会更小。」或「只裁掉了几段过长的工具输出，没有需要总结的历史。」
- 对话正在进行时不能压缩，会提示「对话正在进行中，等它结束再压缩。」对话太短时提示「对话还太短，没什么可压缩的。」
- 完成后显示「已压缩上下文：N 条消息整理为 M 条，完整对话仍可查看。」中途取消时，原上下文保持不变。

## 压缩后保留什么、丢什么

- **原样保留**：最近的几轮对话（最多约占窗口的 12%，至少 4 条消息），正在改的文件内容一般都在这里。
- **变成摘要**：更早的对话。摘要按固定结构写：原始目标、你提过的约束和偏好、已完成和未完成的任务、关键结论、下一步、需要的文件路径和报错信息；另外附上读过和改过的文件清单、你最近一次的请求。
- **丢掉的**：较早消息的原文细节，包括早先的工具输出和思考过程。压缩后的对话一般控制在窗口的三成以内。
- **没有真的消失**：界面上完整对话仍然可以翻看；agent 需要时可以用 `recall` 工具从会话记录里把原文找回来。
- 压缩会重写发给模型的前缀，紧接着的一次请求提示词缓存不命中，会比平时贵一些。

## 实用建议

- 长任务换一个新话题时，开新对话比反复压缩更省，也能拿回全部窗口。
- 希望压缩后一定记得某件事，用 `/compact` 加说明，而不是等自动压缩。
