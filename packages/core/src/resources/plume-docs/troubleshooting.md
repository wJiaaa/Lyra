# 常见报错：是什么意思、怎么办

## 「该目录不在已打开的项目内」/「该路径不在已打开的项目内」

**意思**：Plume 只在你打开过的地方改东西。会改仓库或文件的操作，目标目录必须在以下几处之一：已打开项目的任一源文件夹、不在项目里的会话自己的目录（`~/.plume/workspaces/`）、Plume 的工作树目录（「设置 › Worktrees › 工作树根目录」，留空时是 `~/.plume/worktrees`）。不在这些地方就拒绝，弹出这句提示。

- 「该目录不在已打开的项目内」出自 Git 面板：暂存、取消暂存、放弃改动、提交、生成提交说明、推送、拉取、刷新（询问远端）、新建 / 切换 / 删除分支、删除工作树、初始化仓库。查看改动、历史、分支对比这些只读的不受影响。
- 「该路径不在已打开的项目内」出自文件树：新建、重命名、复制、移动、删除。

**常见的几种情况**：

1. 开了「设置 › Worktrees › 新建会话时自动创建独立工作树」，而「工作树根目录」留空。这时每个新会话的工作树建在项目**旁边**（仓库所在目录的上一级里，名为 `<仓库名>-<8 位编号>`），既不在项目里，也不在默认的工作树目录里，于是在这些会话里用 Git 面板提交、推送都会报这句。
2. 在 Git 面板里切到了一个放在项目外面的工作树（Git 面板会把仓库的所有工作树都列在仓库下面，包括你自己在别处 `git worktree add` 出来的）。
3. 会话所在的项目已经从侧栏移除（移除时它的会话会被归档，从「设置 › 已归档的聊天」打开后就是这种情况），或那个文件夹已经在「编辑项目」里被移出了项目。

**怎么办**：

- 把这个目录加进项目：侧栏右键项目 › 编辑项目 › 添加，选这个目录，保存。或者「新建项目」直接指向它。加进去立刻生效。
- 情况 1：在「设置 › Worktrees › 工作树根目录」填一个目录（比如 `~/.plume/worktrees`）。之后新建的工作树都放在那里，Plume 认得。已经建在项目旁边的那些，用上一条的办法加进项目。
- 情况 3：重新「新建项目」把那个文件夹加回来。
- 只是想临时操作一下：在终端里自己跑 git，或者让 Agent 在对话里做（Agent 的命令走的是权限审批，不受这条限制）。

## 「还没有可用的模型，先到「模型设置」里添加一个服务商。」

没配置任何模型，或者这个会话选的模型已经找不到了（模型被删，或它所属的服务商被关掉）。去「设置 › 模型设置」添加 / 打开服务商；已有别的模型时，在输入框的「选择模型」里换一个。配置方法见 `plume://models`。

## 模型请求失败：密钥、模型名、额度

请求被服务商拒绝且重试没有意义时，对话里会停下并显示一行原因：

- 「密钥被拒绝」「没有访问权限」（HTTP 401 / 403）：API Key 不对或过期。
- 「模型或地址不存在」（HTTP 404）：模型名或接口地址写错了。
- 「额度不足」「账号已停用」：去服务商后台看余额和账号状态。
- 「请求不被接受」「请求内容过大」「请求参数不合法」：这次请求本身有问题，换个说法或先 `/compact` 压缩上下文。
- 「内容被安全策略拒绝」：服务商的内容审核拦下了。

前两类那一行旁边有「去设置」按钮，直接跳到「设置 › 模型设置」。改好后可以在那个服务商的编辑页点「测试」检查：成功会显示「连接成功，<模型> 响应正常」，否则显示原因，比如「<N> 秒内没有收到回复」。

## 「连接中断，N 秒后重试（第 n 次）」「服务端故障……」

网络断开、超时、限流（429）、服务端 5xx 这类临时故障，Plume 会自动重试，接上后那一行变成「断了一下，已恢复」或「重试 N 次后恢复」。如果显示「……已重试 N 次，一直是同一个错误」，多半不是临时故障，鼠标移到那一行看原文。重试次数和间隔在「设置 › 常规 › 请求重试」里调；点停止可以立即取消等待。

## MCP 服务「连接失败」「缺少密钥」「需要登录」

对话里出现「MCP 服务器「…」没有连上：…」时，去「设置 › 插件」的「MCP」标签看那张卡片：

- 「连接失败」：卡片上是具体报错，stdio 服务还附「服务器 stderr 的最后几行」。旁边的「重新连接」可以立刻再试一次。连接限时 30 秒，用 `npx`、`uvx` 第一次启动时放宽到 180 秒，第一次超时多半是在下载，再连一次试试。
- 「缺少密钥」：先在「密钥与配置」里填值，服务才会启动。
- 「需要登录」：远程服务器要 OAuth 登录。点卡片上的「登录」，在浏览器里授权完会自动回来。令牌续不上或服务器要更大权限时也会回到这个状态，再登录一次即可。
- 「重连中（第 n 次）」：断线后在自动重连，最多 8 次；等不及可以点「重新连接」。

详见 `plume://mcp`。

## 其他

- 「文件夹已经不在了：<路径>。可以在项目菜单里把它从列表移除。」——项目文件夹被删或被挪走了。挪回原处，或右键项目 › 移除。
- 「<路径> 读不出来（<原因>），这次按默认设置运行……」——`~/.plume/settings.json` 写坏了，服务商、MCP、hooks 都没加载。修好文件后重启 Plume；在那之前保存设置，Plume 会先把原文件另存一份再写入。
- 「Plume 打不开会话记录」——`~/.plume/sessions/sessions.db` 打不开。先退出其他正在运行的 Plume 再打开；还是不行，把 `sessions.db` 连同旁边的 `-wal`、`-shm` 文件一起挪走，Plume 会新建一个（原来的会话就不在列表里了）。
