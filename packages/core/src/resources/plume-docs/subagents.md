# 子智能体：有哪几种、什么时候派、怎么选模型、怎么自定义

子智能体是 Plume 在对话里派出去单独干一件事的助手。它在自己的上下文里工作，只把最后的结果交回主对话，所以它翻过的大量文件和日志不会挤占主对话的上下文。

## 内置的七种

| 名字 | 用途 | 能用的工具 |
| --- | --- | --- |
| `general` | 通用研究与代码修改（不指定时默认派它） | 主会话的全部工具 |
| `explore` | 只读搜索与代码定位，交回结论和相关文件 | 读、搜索、列目录、终端 |
| `review` | 检查代码缺陷与风险，只报具体缺陷，不报风格偏好 | 读、搜索、列目录、终端 |
| `verify` | 跑一项检查（测试、类型检查、构建、lint）并报告结果，不负责修 | 读、终端 |
| `plan` | 只读分析与实施规划，交回步骤、风险和未确定的地方 | 读、搜索、列目录 |
| `simple` | 量大但机械、边界清楚的改动，批量做完 | 主会话的全部工具 |
| `reason` | 先想清楚再动手的难题 | 主会话的全部工具 |

## 什么时候会派

由 Plume 自己判断。值得派的是两类活：中间产出很大、只需要结论的（翻几十个文件找一个答案、跑一个输出很长的命令看哪里失败），以及和手头工作无关的一整块独立的活。一两步就能改完的、正在写的东西的一部分，它会自己做。

想指定某个子智能体，在输入框里敲 `@`，从「智能体」一组里选，或直接写 `@名字`，比如「让 @review 看一下这次的改动」。

- 同时最多跑 4 个，多出来的排队依次开跑。上限可以在 `~/.plume/settings.json` 里用 `maxConcurrentSubAgents` 调，范围 1–8。
- 只有主对话能派，子智能体不能再派子智能体。
- 子智能体要做有风险的操作时，审批卡片照常弹给你，卡片上会写明是哪个子 Agent 在请求。
- 计划模式开着时，派出去的子智能体同样只能读。
- 派出后输入框上方会出现一行进度，点开是子 Agent 面板，能看到每个子智能体的全过程，也可以给还在跑的那个补一句话（纠偏、补充信息，或让它收尾），或者停止它。

## 给子智能体选模型

在「设置 › 智能体」里，每个子智能体一行，右侧可以选模型和思考等级。还没打开任何对话时也能提前设置。

- 模型选「跟随主会话」就用当前对话的模型。定义里自己写了模型、且本机配置里找得到时，显示为「遵循定义」。
- 在这里单独选的模型优先于一切；思考等级只在所选模型支持思考时出现。
- 改动保存后，从下一次派发开始生效。
- 同一页「会话」一组里还有持续目标裁判、侧边聊天、智能标题等辅助模型的设置。

## 自定义子智能体

在「设置 › 智能体」点「新建」，填写调用名（小写字母开头，可用小写字母、数字、`-`、`_`）、用途（展示给模型，它据此决定什么时候派）、允许的工具（全部，或勾选一部分）和指令，选择生效范围（「所有项目」或当前项目）后保存。

- 点内置子智能体的那一行可以编辑它，保存后成为你的自定义版本，原版可以随时用「恢复 … 的内置指令」找回。
- 也可以复制一个现有的再改。

也可以直接写文件：每个子智能体一个 Markdown 文件，放在 `<项目>/.plume/agents/`（只在这个项目生效）或 `~/.plume/agents/`（所有项目）。不读子目录。

```markdown
---
name: code-reviewer
description: 按团队规范审查改动
tools: [read, grep, glob]
model: 某个模型 id
---
你是代码审查助手……（这里是它的指令）
```

`tools` 不写表示允许全部工具；`model` 可选，本机找不到这个模型时跟随主会话。同名时项目里的优先于个人的，两者都优先于内置的。
